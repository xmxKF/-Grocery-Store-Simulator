# GDD.md — 《小店经营者》游戏设计文档

> 本文件是**数值与行为的唯一权威**。`CONTRACTS.md` 定义接口，本文件定义要填进接口的每一个数字。
> 工程师按此实现，**不得自行发挥数值**。视觉见 `DESIGN.md`。

## 1. 一句话概述
第一人称经营一家小超市：用电脑订货 → 搬箱上架 → 给商品定价 → 亲手扫码收银找零 → 日结算算利润 → 升级解锁更多商品与货架。

## 2. 核心循环
```
备货阶段(时钟暂停) ─┐
  ├ Tab 开电脑：订货 / 改价 / 买许可证
  ├ 卸货区搬箱 → 走到货架格 → 逐件上架 → 空箱丢垃圾桶
按 O 开门营业 ──────┤
  ├ 顾客按频率进店 → 找货 → 拿货 → 排队
  ├ 玩家跑到收银台 → 逐件点击扫码 → 收现金找零 / 刷卡
时钟走完(300s) ─────┤
  ├ 停止生成顾客，场内顾客走完
  └ 日结算面板：营业额 / 进货成本 / 固定支出 / 净利 → 次日备货
```
一天目标：净利为正，攒钱扩品类，攒 XP 升等级。

## 3. 订货系统（`G.shop.orderBox` / 电脑「订货」页）
- 订货只能在**仓储电脑**（后墙）操作：走近按 `E`，或任意时刻按 `Tab`。
- 单位为**箱**。箱价 = `进价 × boxSize + 配送费`；**配送费固定 ¥3 / 箱**。
- 购物车：单次最多 **8 箱**（等级 9 后 12 箱）。点「确认下单」立即扣款，余额不足则按钮禁用。
- 送达：下单后 **`deliverySec = 25` 秒**，箱子逐个（间隔 0.4s）生成在**门外卸货区**，并 `emit('delivery')`。
- 卸货区同时存在的箱子（含空箱）上限 **12**；达到上限时订货按钮禁用并提示「卸货区已满」。
- 备货阶段与营业中都可订货，配送计时照常走（`G.shop.update(dt)`）。
- 只能订购**已解锁**商品（等级 ≥ unlockLevel 且已持有该类目许可证），见 `G.shop.isUnlocked`。

## 4. 上架系统
- 箱子交互：准星对准箱子（≤3m）按 `E` / 左键 → **举起**（挂相机前方 0.6m，下方 0.35m）。举箱时移速 ×0.8。
- 手持箱对准**货架格**按 `E` / 左键 → 放入 1 件，操作冷却 **0.25 秒**，箱内 `itemsLeft -1`。
- **货架格容量 = 该商品的 `slotCap`**（见商品表）。一个格子只能放一种商品；格子非空且商品不同 → 提示「此格已被占用」，不可放。
- `itemsLeft` 归零 → 箱体变为空箱（材质变暗），仅能丢垃圾桶。丢弃空箱 **+1 XP**。
- `Q` 键：把手持箱放到脚下地面（保留剩余件数）。
- **货架格位总量**：
  | 阶段 | 普通货架 | 格位 | 冷藏柜 | 冷藏格位 | 合计 |
  |---|---|---|---|---|---|
  | 开局(Lv1) | 4 组 | 24 | 0 | 0 | 24 |
  | Lv3 | 5 组 | 30 | 买生鲜许可证后 2 台 | 12 | 42 |
  | Lv6 | 6 组 | 36 | 2 台 | 12 | 48 |
  | Lv8 扩建 | 8 组 | 48 | 2 台 | 12 | 60 |
  - 每组普通货架 = 6 格（3 列 × 2 层，层高 0.9m / 1.4m）。每台冷藏柜 = 6 格。
  - **生鲜类（cat=生鲜）只能放冷藏柜；其他类目不能放冷藏柜。** 违规时提示「该商品需冷藏」/「冷藏柜仅限生鲜」。

## 5. 定价系统（电脑「定价」页）
- 每个商品有固定**市场价 `market`**（不随时间波动，见商品表）。
- 玩家售价 `G.state.prices[pid]` 默认 = `round(market × 1.20, 0.1)`；允许区间 `[0.1, market × 3]`。
- **顾客容忍度公式**（`r = 售价 / market`，逐件判定）：
  | r 区间 | 购买概率 p | 附加效果 |
  |---|---|---|
  | r < 0.95 | 1.00 | **抢购**：该商品需求量 +1 件 |
  | 0.95 ≤ r ≤ 1.10 | 1.00 | 无 |
  | 1.10 < r ≤ 1.40 | `1.00 - (r-1.10)/0.30 × 0.50` | 30% 概率吐槽 toast「有点贵啊…」 |
  | 1.40 < r ≤ 1.70 | `0.50 - (r-1.40)/0.30 × 0.50` | 必定抱怨，**XP -2** |
  | r > 1.70 | 0.00 | 拒买放回，**XP -2**，toast「太贵了，不买了」 |
- 判定为不买 → 该商品**不从货架扣除**，清单中删除该项，继续下一件。
- 改价立即生效，不影响已在场顾客已拿到手的商品。

## 6. 顾客 AI（`js/customers.js`）
- **生成频率**：`interval = clamp(20 - 0.8×(day-1) - 1.2×(level-1), 5, 20) × rand(0.75, 1.25)` 秒。
  仅在 `G.state.open === true` 且**至少有 1 个货架格有货**时生成。
- **同屏上限**：`min(4 + level, 12)`；Lv8 扩建后上限再 +2。
- **购物清单**：条数 `randInt(1, clamp(2 + floor(level/2), 2, 6))`；每条 `{productId, qty: randInt(1,2)}`；
  商品从「货架上有货 且 已解锁」的集合中**不重复**随机抽取。
- **状态机**（严格按 `G.world.nav` 的 waypoint 直线移动，移速 **1.6 m/s**，无寻路）：
  1. `entering` — 从 `nav.entry` 走向第一个目标货架前的 `aisleSpots` 点。
  2. `shopping` — 到位后停 **1.2s**，每件取货耗时 **0.4s**（调 `G.world.removeItem`），逐条处理清单。
     本阶段总时长上限 **45s**；超时则带着已拿商品直接去排队。
     若清单全部落空（缺货或嫌贵）→ 直接 `leaving`，`emit('customerLeft',{angry:false,reason:'no_stock'})`，**XP -1**。
  3. `queueing` — 走到 `nav.queueSpots` 空位（共 5 个）。队列已满 → 弃购离店，`angry:true, reason:'queue_full'`，**XP -2**（商品视为损耗，计入 cogs）。
     **耐心 `patienceSec = 60` 秒**从入队开始计时，超时 → 弃购离店 `angry:true, reason:'impatient'`，**XP -3**，商品计入损耗。
  4. `paying` — 队首走到 `nav.registerFront`，把商品逐件放上传送带（0.2s/件）。等待玩家扫码。
  5. `leaving` — 从 `nav.exit` 走出，2 秒后销毁 mesh。
- 顾客外形：低多边形（Box 身体 0.45×1.0×0.3 + Box 头 0.28³ + 两条 Box 腿），随机取 `DESIGN.md` 顾客色板一色。**无碰撞、可互相穿过**。

## 7. 收银系统（`js/checkout.js` + `#pos`）
- 走近收银台按 `E` → `enterRegister()`：锁定视角朝传送带，显示 POS 面板；`Esc` 退出。
- **扫码**：左键点击传送带上的商品 mesh → 小计累加 `G.state.prices[pid]`，商品移入「已扫区」，冷却 **0.3s**，**每件 +2 XP**。
- 扫完点「结算」：
  - 若仍有**未扫商品** → 这些商品白送：`G.addMoney(-Σ进价, 'miss_scan')`，**XP -3**，toast「漏扫了！」。
  - 付款方式随机：**刷卡 55% / 现金 45%**。
- **刷卡**：点击读卡器按钮 → 1.0s 动画 → 成交。
- **现金找零小游戏**：
  - 顾客给出面额 = 用 `{100,50,20,10,5,1}` 贪心凑出的、**≥ 总额的最小组合**（例：总额 ¥13.4 → 给 ¥20）。
  - 玩家用找零面板按钮拼出找零：`¥0.1 ¥0.5 ¥1 ¥5 ¥10 ¥20 ¥50 ¥100`（点击累加，「清空」重置）。
  - 点「确认找零」，`diff = 玩家给出 - 应找`：
    | diff | 结果 |
    |---|---|
    | = 0 | 完美，**XP +3** |
    | > 0（多找） | `G.addMoney(-diff,'change_error')`，**XP -3**，toast「找多了…」 |
    | < 0（少找） | **XP -5**，toast「顾客投诉找零不足」，不补钱 |
- **成交**：`G.addMoney(total,'sale')` → `G.addXP(+5)` → `dayStats.revenue += total`、`cogs += Σ进价`、`itemsSold += n`、`customers += 1` → `emit('sale')` → 顾客转 `leaving`。

## 8. 昼夜 / 营业循环（`js/main.js`）
- **备货阶段**：每日开始，`G.state.open = false`，时钟不走。HUD 常驻提示「按 O 开门营业」。
- **营业**：按 `O` → `open = true`，`clock` 从 0 走到 **`dayLengthSec = 300` 秒**（实时）。
  HUD 时钟映射为店内时间 **09:00 → 21:00**（1 店内小时 = 25 实时秒）。
- **打烊**：`clock ≥ 300` → 停止生成顾客，`open = false`；场内顾客全部离场后触发 `dayEnd`。
  营业中可随时按 `O` 提前打烊（已进店顾客照常结账完）。
- **日结算面板 `#screen-summary`**（`summary` payload）：
  - `revenue` 当日销售额
  - `cogs` 当日售出 + 损耗商品的进价合计
  - `rent` **固定支出合计** = 房租 + 水电 + 员工工资
    - 房租：**¥40 / 天**，Lv8 扩建后 **¥80 / 天**
    - 水电：每组普通货架 **¥2**，每台冷藏柜 **¥4**（开局 4 组 = ¥8）
    - 员工工资：雇佣收银员后 **¥60 / 天**
  - `profit = revenue - cogs - rent`
  - `customers`、`itemsSold`
  - 面板底部「进入第 N+1 天」按钮 → `day+1`、清空 `dayStats`、自动 `G.save()`。
- **资金规则**：余额可为负但不能主动消费（订货/买许可证/雇佣需余额足够）。
  日结算后余额 < 0 显示红色警告；**连续 3 天日结算余额 < 0 → 游戏结束**，回主菜单（存档保留可重开）。

## 9. 进度系统
- **XP 来源汇总**：扫码 +2/件、成交 +5/单、完美找零 +3、丢空箱 +1；
  抱怨 -2、拒买 -2、空手离店 -1、队列满/不耐烦 -2/-3、多找 -3、漏扫 -3。XP 不低于 0。
- **等级表**（`G.data.LEVELS`，`xpNeeded` 为**累计**值）：
  | Lv | 累计 XP | 解锁内容 |
  |---|---|---|
  | 1 | 0 | 开局持有【食品】【饮料】许可证；4 组货架（24 格） |

  | 4 | 320 | 巧克力 / 茶饮 / 鸡蛋 |
  | 5 | 550 | 咖啡 / 牛奶 / 洗衣粉 |

  按玩家设定价格 100% 收款，但**只给 50% XP**，且不触发找零小游戏。可随时解雇（不退雇佣费）。

## 13. UI 界面清单（对应 `index.html` 固定 DOM id）
1. `#screen-menu` 主菜单：标题、新游戏、继续（有存档时可用）、操作说明。
2. `#hud`：`#hud-money` 余额（左上）、`#hud-day` 天数 + `#hud-clock` 店内时间（顶部居中）、`#hud-level` 等级 + XP 进度条（右上）。
3. `#crosshair` 准星；`#prompt` 交互提示（底部居中）；`#toast` 浮动消息（右下，2.5s 淡出，最多堆 3 条）。
4. `#screen-computer` 仓储电脑，三个标签：
   - **订货**：商品列表（图标色块 / 名称 / 进价 / 箱价 / 每箱件数 / 库存数），`+/-` 加入购物车，右侧购物车与「确认下单」。
   - **定价**：商品 / 市场价 / 当前售价（数字输入 + `±0.1` 按钮）/ 倍率标签（绿 ≤1.10、黄 ≤1.40、红 >1.40）。
   - **许可证**：4 个类目卡片（已持有 / 可购买 + 价格 / 需等级 N）；Lv10 起显示雇佣收银员卡片。
5. `#pos` 收银 POS：已扫商品列表、小计、结算按钮、付款方式区（读卡器按钮 或 现金找零面板）。
6. `#screen-summary` 日结算：营业额 / 进货成本 / 固定支出 / **净利**（正绿负红）、顾客数、售出件数、「进入第 N 天」。
7. 升级提示：复用 `#toast`，文案「等级提升！Lv N — 解锁：xxx」。

## 14. 明确的范围裁剪（不做）
- ❌ 联机 / 4 人 co-op（纯单机）
- ❌ 雇员寻路与搬货 AI（仅 Lv10 站桩收银员）
- ❌ 家具自由摆放 / 店铺布局编辑（布局写死在 `world.js`）
