## 0. 背景与定位

这是一次大改造拆分出的第一个子项目。用户提出的 6 项诉求被拆为 4 个独立子项目，各走一轮 spec → plan → 实现：

| | 子项目 | 内容 |
|---|---|---|
| **A** | 手感修复包（本文档） | 收银台站位、货架价签、过渡动画 |
| B | 美术方向升级 | 模型精度、材质、阴影；需重写 DESIGN.md §5 |
| C | 大卖场扩张 | 大地图、多收银台、仓库、寻路、经济重平衡 |
| D | 物理与投掷 | 抛物投掷、NPC 击飞、拾取与物品栏 |

A 排在最前的两个理由：一是三项改动都局部且便宜；二是 #1 产出的「站位（stance）」抽象是 C 的多收银台的前置件。

B 排在 C 之前的理由：B 会抬高每个物体的多边形与材质开销，C 会把物体数量放大数倍，两者叠加有帧率风险。先在小地图上做 B 等于先定下「每类物体的多边形预算」，C 再按预算铺开；反过来做等于先建大卖场再全店翻新。

**A 不包含**：任何地图布局改动、任何多收银台准备工作、任何材质/阴影升级。这些分别属于 C 和 B。

## 1. 问题诊断（已核实，非推测）

### 1.1 收银台视角被钉死

`checkout.js:432 startCamLock()` **不移动玩家**，只把相机从玩家当时所站位置 slerp 到 `lookAt(beltFrame().origin)`。同时 `player.js:163` 令 `blocked = screenIsOpen || registerActive`，第 173 行直接 `return`，鼠标视角被完全关闭，第 166 行还主动 `exitPointerLock()`。

结果：在哪个角度按下 E，就被固定在哪个角度斜看收银台，无法调整。

**指针锁定是故意释放的**，不是疏忽：扫码用自由鼠标光标点击传送带上的商品 mesh（`checkout.js:551` 收集未扫商品做射线检测），POS 面板也需要点击。自由光标与鼠标视角互斥。所以正确的修法不是「补一个视角控制」，而是**保证站位与取景一开始就正确，从而不需要调**。

次要成因：`lookAt` 的目标 `beltFrame().origin` 是柜台近侧边缘，**不是商品实际所在位置**（见 §3.2 坐标推导），本身就偏。

### 1.2 货架格挡板

`world.js:264` 每格生成一个 `0.55 × 0.5 × 0.05` 的 Box（变量名 `marker`），既是视觉挡板也是射线靶子（`world.js:273` 注册为 `shelfSlot`）。

朴素改法（直接把挡板换成细价签条）会把射线靶子面积压到约 1/8，瞄准手感显著变差。必须把「视觉」与「靶子」拆成两个物体。

### 1.3 过渡动画

核实结论与用户初始描述不同，如实记录：

- **扫码滑动已实现且工作**：`checkout.js:256 stepSlides` 在 150ms 内把商品从传送带 lerp 到已扫区。但用的是**线性插值**，而 DESIGN.md §6 要求全项目统一 `ease-out`。它「能动但发木」。**这项是调参，不是重写。**
- **上架确实没有位移**：`world.js:331 popInItem` 只在目标位置原地做 0.8→1.0 缩放 90ms。用户所说的「瞬移」即此。

**连带发现（非用户提出，但为本次改动所必需）**：`world.js:306 updateSlotVisual` 每次上架都销毁并重建该格全部商品方块，且每个方块都 `new THREE.BoxGeometry`。飞行动画一旦引入，这个重建会把飞行中的 mesh 一起冲掉。因此增量化是 §4.1 的前置改动，属于「本次改动造成的必要修整」，计入 A 的范围。

## 3. 设计：#1 收银台站位系统

### 3.1 核心抽象

`checkout.js` 持有一个 stance：

```js
stance = { pos: THREE.Vector3, yaw: Number, pitch: Number }
```

**stance 由传送带几何反推，不硬编码坐标。** 这是 C 做多收银台时每个收银台自动各有各站位的关键，也是 A 作为 C 前置件的意义所在。

### 3.2 坐标推导（依据现有几何核算）

现有几何（`world.js:153 buildCheckout`）：

- 柜体 `BoxGeometry(1.2, 1.0, 2.0)`，中心 `(-7.0, 0.5, 0)`
- 传送带 `BoxGeometry(0.9, 0.08, 1.6)`，中心 `(-7.0, 1.04, 0)`
- 柜台 collider `x ∈ [-7.6, -6.4]`，`z ∈ [-1.0, 1.0]`
- `nav.registerFront = (-6.2, 0, 0)`（顾客侧）
- 西墙内表面 `x ≈ -7.9`

由 `beltFrame()` 推出：

- `dir = (-1, 0, 0)`（由顾客侧指向柜台，即指向 -x）
- `side = (0, 0, -1)`
- `halfSide = 0.8`
- `origin = (-6.82, 1.08, 0)`

由 `beltPos(i)` 推出商品实际落点（`cols = 5`）：

- `y ≈ 1.19`
- `z ∈ [-0.10, 0.62]`（每列间隔 0.18，最多 5 列）
- `x ∈ [-7.22, -6.82]`（每多一排沿 dir 后退 0.2）

**结论：商品场的中心约在 `(-7.0, 1.19, 0.26)`，而现有 `lookAt` 目标是 `origin = (-6.82, 1.08, 0)`——偏了。**

站位取：

```
stance.pos = beltFrame().origin + dir × 0.93 + (0, 1.65 - origin.y, 0)
           = (-7.75, 1.65, 0)
```

即柜台背侧、西墙与柜台之间的 0.3m 空隙，正是雇佣收银员站桩所在处（`world.js:204`）。玩家因柜台 collider 平时走不进去，但**收银模式下移动已禁用，把相机放进去无副作用**。

朝向取：`lookAt(商品场中心)` 而非 `lookAt(origin)`。由上述坐标算得俯角约 **-30°**。

### 3.3 取景验证

`fov 70` 垂直、16:9 时水平 FOV ≈ 102°。商品场 z 向展开 0.72m，距相机约 0.79m，占约 48° 水平视角——可容纳。

但 `#pos` 面板固定占据屏幕右侧 340px（DESIGN.md §4）。因此 **yaw 需要偏置，使商品场落在画面左侧约 65% 区域内**，避免被 POS 面板遮挡。

**这是本设计中唯一需要实测调参的量**（后退距离 0.93、俯角、yaw 偏置三者联调）。验收标准见 §6.2。

### 3.4 进入 / 退出流程

```
enterRegister():
  savedPose = {pos, yaw, pitch}          // 从 G.player 取，不从相机反推
  stance = computeStance(beltFrame())
  300ms ease-out 同时插值 位置 与 朝向 → stance
  到位后位姿完全冻结
  （若收银员站桩可见，临时隐藏；见 §3.5）

exitRegister():
  300ms ease-out 插值回 savedPose
  明确把 pos/yaw/pitch 交还 G.player
  （恢复收银员站桩可见性）
```

`player.js` 的 `wasBlocked` 分支（`player.js:176`）现在从相机反推 `yaw/pitch/pos`——这正是退出后位置被改乱的来源。改为：**收银模式退出时由 `checkout` 显式还原，`player` 不再从相机猜**。全屏界面（computer/summary/menu）不移动相机，其 `wasBlocked` 路径保持原样。

### 3.5 边界情况：已雇佣收银员

Lv10 雇佣的站桩收银员位于 `(-7.75, 0, 0)`，与 stance 重合。处理：`enterRegister` 时临时 `setCashierVisible(false)`，`exitRegister` 时按 `G.state.cashier` 恢复。不改动 `setCashierVisible` 的幂等语义。

## 4. 设计：#2 价签与射线靶子

原 `marker` 挡板删除，拆为两个物体。

### 4.1 价签（视觉）

- 几何：`BoxGeometry(0.55, 0.06, 0.04)`，厚度 0.04 与层板一致（`world.js:244`）
- 位置：贴在该格**下方层板**的前缘。层板在 `slotY - 0.04`，前缘在 `frontZ`。故价签置于 `(slot.pos.x, slotY - 0.055, frontZ + facing × 0.02)`
- 正面用 `CanvasTexture` 渲染两行文字：商品名 / `¥价格`

三种状态：

| 状态 | 条件 | 表现 |
|---|---|---|
| 有货 | `productId != null && count > 0` | 类目色底 + 商品名 + 价格 |
| 缺货 | `productId != null && count === 0` | 黄底（`--warn` #E8B54C）+ 商品名 + 「缺货」 |
| 空格 | `productId === null` | 灰底（货架框架色 #8C9AA6）+ 「空」 |

**准星命中高亮的载体从挡板转移到价签**。DESIGN.md §6 要求命中时目标 `material.emissive` 变 `#FFD666`、`emissiveIntensity 0.35`，移开还原（缓存原值，禁止克隆材质）。靶子不可见，必须由价签承担这个可见反馈。

刷新时机：`addItem` / `removeItem` / `G.shop.setPrice` 之后，以及 `restoreShelves` 与 `syncLayout` 之后。

**贴图缓存**：按 `(productId, price, 状态)` 三元组缓存 canvas texture 并复用。24 种商品 × 有限价格档 × 3 状态，规模可控。禁止每次上架都新建 canvas 与 texture（否则等于把 §1.3 的泄漏问题换个地方重犯）。

### 4.2 靶子（交互）

- 几何：`BoxGeometry(0.55, 0.46, 0.5)`，材质 `transparent: true, opacity: 0`
- 位置：`(slot.pos.x, slotY + 0.23, frontZ - facing × 0.25)`——占据该格商品应在的那块空气，并延伸至货架前表面
- 注册为 `shelfSlot`，取代原 `marker`

高度取 0.46 而非 0.5：`SLOT_HEIGHTS = [0.9, 1.4]` 间距 0.5，取 0.46 让上下两格靶子之间留 0.04 空隙，避免边界处拾取歧义。

瞄准面积与原挡板持平（0.55×0.5 → 0.55×0.46），且语义更正确：对准「要放东西的地方」而非对准一块板。

**实现注意**：Three.js r128 的射线检测对 `visible === false` 的物体行为需实测确认，因此靶子采用 `opacity: 0` 而非 `visible = false`，确保必定可被 raycast 命中。

## 5. 设计：#5 动画与增量更新

三件事有依赖顺序，必须按序实现。

### 5.1 `updateSlotVisual` 增量化（前置）

现状（`world.js:306`）：每次调用清空并重建该格全部商品方块，每个方块 `new THREE.BoxGeometry(0.16, 0.22, 0.16)`。

改为：

- 几何体提升为模块级共享常量（一个 `BoxGeometry` 实例，全部商品方块复用）
- count 增加时只在末尾追加一个方块；count 减少时只移除末尾一个方块
- 商品种类变化（`productId` 改变）时才整格重建
- 移除的 mesh 只从 group 摘除，不 dispose 共享几何体

这是飞行动画的前置：否则飞行中的临时 mesh 会被重建冲掉。

### 5.2 上架飞行

`addItem` 成功后：

1. 在**纸箱当前世界坐标**生成一个临时商品方块（复用共享几何体 + 该商品材质）
2. **180ms `ease-out` 直线**飞向目标格位的世界坐标
3. 到达后销毁临时 mesh，并让正式方块以现有 90ms 0.8→1.0 缩放弹入

多件并发飞行各自独立持有自己的动画状态，长按 E 连续上架时互不干扰。无弧线、无翻转（用户已确认选择「直线快递」而非抛物线）。

若飞行途中该格被清空或商品种类改变，飞行中的临时 mesh 直接销毁，不做补偿。

### 5.3 扫码滑动加缓动

`checkout.js:261` 的 `s.t` 线性推进后直接 `lerpVectors`，改为对插值因子套 ease-out。时长维持 150ms（DESIGN.md §6 已规定，不改）。

## 7. 明确不做

- 不改动任何地图布局、collider、nav 点（属于 C）
- 不新增受限自由视角系统——固定站位的取景保证正确，因而不需要（用户已确认）

- 不改材质、不加阴影、不提升模型精度（属于 B）
- 不为多收银台做除 stance 抽象之外的任何准备工作（属于 C）
