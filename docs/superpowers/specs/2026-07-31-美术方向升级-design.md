## 0. 背景与决策来源

子项目 A（手感修复包）已完成。B 解决用户的核心抱怨：**模型太"塑料"——无纹理、无阴影、实体间难以区分**。

设计经两条独立路线盲测产生：Opus 与 Codex 各自基于代码出完整架构方案，互不可见，编排者综合最优。关键盲测收益：Codex 方案中的 `setColorAt` 实例颜色路线被 Opus 的 shader 逆向证伪（本地 r128 构建缺 `USE_INSTANCING_COLOR` 分支，会静默全白）；Codex 纠正了实例数上限（现有 `slotCap` 最大 15，可达上限 900 而非 960）并贡献「根节点 y 恒 0」的步态结构原则。

### 已锁定决策（用户四连确认）

1. **方向**：程序化纹理暖色风——表面纹理全部 `CanvasTexture` 运行时生成，开 PCFSoft 软阴影；保留低多边形骨架
2. **商品**：品类基础形 + 商品变形——8 套共享几何，同类内按商品变尺寸/主色/标签
3. **顾客**：三色分离 + 发型 + 胖瘦随机 + 行走动画（无骨骼）
4. **性能**：中配为准；`localStorage['gss-lowfx']='1'` 隐藏开关一键回退

### 硬约束（继承项目基线）

Three.js r128 UMD、无构建、ES5、IIFE + `window.G`、file:// 即玩、零网络请求、零外部图片资产。

### 性能基线（实测推算）

满级最坏 ~1310 常驻 mesh ≈ 1310 draw call，其中货架商品方块占 78%；三角形仅 ~1.5 万。**瓶颈是 draw call，不是几何量。**

## 2. 实例化架构（draw call ~1310 → ~357）

### 2.1 分组与生命周期

- 按**商品 pid** 分组：每个上架中的商品一个 `InstancedMesh(baseGeo[product.shape], matForProduct(pid), capacity)`，全店 ≤24 个，惰性创建。
- 组内同色同形，**不使用 `instanceColor` / `setColorAt`**（本构建 shader 缺 `USE_INSTANCING_COLOR`，写入静默无效——此条写入 DESIGN §5 明文，防后人踩坑）。
- 容量 64 起，溢出 ×2 重建换入；`instanceMatrix.setUsage(THREE.DynamicDrawUsage)`；`mesh.count` 只画有效数。
- **必须 `frustumCulled = false`**：r128 InstancedMesh 无 `computeBoundingSphere`，默认剔除按原点包围球计算会整组消失。

### 2.2 增删：rebuildProduct(pid)

单函数全量重建：遍历 `allSlots` 找该 pid 且 `count>0` 的格，逐格写 `min(count,16)` 个矩阵（位置=itemLocalPos+itemGroup.position，缩放=product.scale），设 `mesh.count`，`instanceMatrix.needsUpdate=true`。O(60) 遍历 + O(n) 矩阵，微秒级。`updateSlotVisual(slot)` 语义改为：`rebuildProduct(旧pid)` + `rebuildProduct(新pid)`。**无空闲表、无索引映射、无碎片。**

每帧成本为零——只在 addItem / removeItem / restoreShelves / syncLayout 时触发。

### 2.3 与既有系统的关系（A 的交付物全部保全）

- **准星高亮 / 射线**：`itemGroup` 商品堆从来不在 interactable 链路里（hover 只打价签+命中盒 holder）——实例化与其完全正交，**player.js 零改动**。
- **命中盒**：改 `visible = false`（保留 `opacity: 0` 与现有断言）。已验证本构建 Raycaster 不检查 visible，射线照常命中；渲染器跳过 → 再省 60 draw call。
- **上架飞行**：不改。飞行本就是挂 scene 的独立临时 mesh；仅几何/材质换成 `baseGeo[shape]` / `matForProduct(pid)`。中断销毁逻辑原样。
- **popIn**：改写单实例矩阵（0.8→1.0，90ms rAF）。记 `slot._pop`；任何 `rebuildProduct(pid)` 取消该 pid 挂起的 pop（索引会移位）。竞态下最多丢一次 90ms 缩放。
- **价签不实例化**（明确否决）：每格贴图不同（atlas + per-instance UV 在 r128 需 onBeforeCompile 手写 attribute，复杂度爆炸）；且价签是准星高亮载体，实例化必然共用材质 → 高亮一格全亮，违反 CONTRACTS 职责裁定与 `world.slotTagMatUnique` 断言。60 draw 保留。

### 2.4 draw call 账（Lv10 满级）

items ≤24 / tags 60 / racks 52 / 顾客 14×10=140 / 箱 24 / 收银员 10 / 房间 15 / 传送带商品 ≤12 → **≈357**。自测总闸门定 **< 420**。

## 3. 程序化纹理系统（新模块 js/textures.js）

### 3.1 模块

- IIFE + `window.G.tex`；script 顺序插在 `state.js` 之后、`world.js` 之前。CONTRACTS.md 文件清单、script 顺序、`G.tex` API 同步登记（T1 文档任务先行）。
- `G.tex.on`：模块加载时读一次 `localStorage['gss-lowfx'] !== '1'`。**每个生成器在 `!on` 时直接返回 null**——调用方 `flatMat(hex, { map: G.tex.floorWood() })`，`map:null` 天然退化纯色。零分支、零双版本材质；lowfx 路径与升级前构建逐字节等价。切换需刷新页面（隐藏开关，可接受）。
- **双层缓存契约（对抗式审查修订）**：Three.js 的 `wrap`/`repeat` 属于 **Texture 对象**而非材质或 mesh——不同尺寸表面若共用同一 Texture 实例，后设置的 repeat 会覆盖先前所有使用者，纹理密度全局错乱。因此缓存分两层：
  1. **像素源层**：`canvas` 按 `(生成器名, 内容参数)` 缓存（如 `labelBand` 的 `(shape, accent)`）——昂贵的 2D 绘制只发生一次；
  2. **纹理实例层**：`CanvasTexture` 按 `(生成器名, 内容参数, repeatX, repeatY)` 缓存——**repeat 与 wrap 是缓存键的一部分**。相同 repeat 的表面共享同一 Texture；不同 repeat 的表面**必须**得到不同的 Texture 实例（共享底层 canvas，GPU 各自上传一份，256² 级别开销可忽略）。
  - 生成器签名统一为 `G.tex.xxx(repeatX, repeatY, ...内容参数)`；**严禁调用方拿到纹理后自行改 `repeat`/`wrapS`/`wrapT`**（写入 DESIGN §5 明文）。

### 3.2 生成器清单

| 生成器 | 用途 | 分辨率 | 贴片 | repeat |
|---|---|---|---|---|
| `floorWood()` | 地板 16×12 | 512² | 2m | (8, 6) |
| `yardConcrete()` | 卸货区 | 256² | 1.75m | (2, 2.9) |
| `wallWainscot()` | 四段墙（含腔裙板+踢脚线，画在纹理下部） | 256×512 | 2m 横向 | (L/2, 1) |
| `ceilingPanel()` | 天花板矿棉格 | 256² | 1.2m | (13.3, 10) |
| `shelfMetal()` | 货架框/背板/层板拉丝 | 256² | 0.5m | (4, 4) |
| `fridgeSteel()` | 冷藏柜框 | 256² | 0.5m | (4, 4) |
| `counterLaminate()` | 收银台柜体 | 256² | 1m | (1.2, 2) |
| `beltRubber()` | 传送带橡胶（近灰度，靠材质色相乘） | 256² | 0.3m | (3, 5) |
| `cardboard()` | 纸箱瓦楞（近灰度） | 256² | 0.45m | (1, 1) |
| `labelBand(shape, accent)` | 商品标签环带，按 (shape,accent) 缓存 | 64² | — | (1, 1) |

- 表中 repeat 为该用途的**典型值，由调用方传入生成器**（如北墙 16.2m 与东墙段 5m 各传各的 `L/2`）；按 §3.1 双层缓存契约，不同 repeat 得到不同 Texture 实例，互不干扰。
- 全部 POT + `RepeatWrapping` + 默认 mipmap（WebGL1 合法）。
- anisotropy 只给 floorWood / yardConcrete：`Math.min(4, renderer ? renderer.capabilities.getMaxAnisotropy() : 1)`——**必须判 renderer null**（无头环境为 null）。
- UV 不改：Box 大面 U 沿长度、V 沿高度，`repeat.set(n,1)` 使腔裙板贴底、横向平铺；Plane 同理。
- 生成总耗时预算 < 20ms（一次性，启动时）。

### 3.3 红线（写入 DESIGN §5）

1. **传送带材质 `.color` 恒为 `#4E5866`**——`checkout.findBeltMesh()` 靠色值全场景搜索定位台面；橡胶纹理做成近灰度靠色相乘。违反则 `beltFrame()` 静默降级、站位系统失效。
2. **纸箱材质保持 `color.set()` 语义**——`updateBoxVisual` 靠改色切换满/空；瓦楞纹理同为近灰度。
3. 色彩管线：**不开 `outputEncoding=sRGBEncoding`、不开 toneMapping**。DOM HUD 不经 3D 管线，开启会让 §1.1 UI 色板与 3D 观感分家；§1.3 全部 hex 都是对线性输出调的。暖色感来源 = 纹理像素值 + HemisphereLight 地面反弹色。

## 4. 光影

### 4.1 灯光（三盏，main.js）

- `HemisphereLight(0xAECBE0 /*天*/, 0xC7BEAF /*地*/, 0.55)`——阴影区的暖色反弹，暖色风的主要来源
- `AmbientLight(0xFFFFFF, 0.12)`——保底不死黑
- `DirectionalLight(0xFFF6E5, 0.85)` @ (8,14,6)，`castShadow = true`（唯一投影灯）

### 4.2 阴影参数

世界 AABB：x∈[-8.2,11.7]、z∈[-6.2,6.2]、y∈[0,3]。→ shadow camera：ortho **±13**、near 1、far 40；`mapSize 2048²`（≈7.9cm/texel）；`bias -0.0004`、`normalBias 0.03`（flatShading Box 用 normalBias 防痤疮不产生 peter-panning）；`renderer.shadowMap.type = PCFSoftShadowMap`。

### 4.3 cast / receive 矩阵

| 物体 | cast | receive | 理由 |
|---|---|---|---|
| 地板 / 卸货区 | ✗ | ✓ | |
| **墙 / 天花板 / 门框柱** | **✗** | ✓ | **无窗室内，壳体投影=全店漆黑；headless 自测看不出来，必须先写断言再动灯** |
| 货架框/层板/背板 | ✓ | ✓ | 层板投在下层，空间感主力 |
| 价签 / 命中盒 | ✗ | ✗ | |
| **商品 InstancedMesh** | **✗** | ✗ | 0.16m 物体在 7.9cm/texel 下只产生噪点；接触暗部由层板投影免费给 |
| 顾客（躯干/头/腿） | ✓ | ✗ | 移动阴影是"活着"的最强信号；发型/臂/鞋不 cast 省一半 |
| 纸箱/收银台/传送带/电脑/垃圾桶/收银员 | ✓ | ✓ | |

阴影 pass ≈134 个深度 draw，总提交 ≈490，中配预算内。lowfx：`shadowMap.enabled=false` 一个布尔。

## 6. 顾客

### 6.1 构造（10 部件；几何初始化时 translate 到枢轴，不加 Group）

| 部件 | 几何 | 尺寸 | y | 材质槽 |
|---|---|---|---|---|
| 鞋×2 | Box | 0.16×0.08×0.22 | 0.04 | shoe |
| 腿×2 | Box(translate 到髋) | 0.15×0.64×0.17 | 枢轴 0.72 | pants |
| 躯干 | Box | 0.44×0.68×0.26 | 1.06 | shirt |
| 臂×2 | Box(translate 到肩) | 0.11×0.58×0.13 | 枢轴 1.34, x±0.28 | shirt |
| 头 | Box | 0.26³ | 1.53 | skin |
| 发型 | 4 款共享几何（短块/侧分/平顶/双侧块） | ~0.29×0.11×0.29 | 1.69 | hair |

随机：身高 `h∈[0.90,1.08]`（group.scale.y）；胖瘦 `w∈[0.88,1.22]` **只作用躯干**（scale x/z）+ 腿距 ±0.115w。存 `c.dims={h,w}`。

色板（DESIGN §1.3 新增）：衣=现有 8 色；裤 `#3A424C #4E5866 #5A6B7A #6E5A48 #2E3742`；肤 `#F0C9A0 #D9A878 #C08B4E #8A5A3B`；发 `#2A2118 #4A3524 #6E5A48 #A8A29A`；鞋 `#2E3742`。材质走模块级缓存，总数 ≤22。

### 6.2 步态（applyGait(c, dt, moving)，customers.js 内唯一写入点）

- `c.phase += dt × customerSpeed × 3.4`（步频 ~0.87Hz）
- 腿 `sin(phase)×0.44`（±25.2°）反相；臂 `−sin(phase)×0.30` 反相；鞋随腿。
- 浮沉：躯干/头/发 各自 baseY + `0.03×|sin(phase)|`。**根节点（c.mesh）y 恒 0**——浮沉只动部件，导航/队列判定/未来物理不受扰动（Codex 原则）。
- 静止：角度按 `k=min(1,dt×8)` 衰减归零，禁止冻在半步。
- D 兼容 = 结构不堵死，不写代码：步态集中在 applyGait（未来 `if (c.ragdoll) return;` 一行）；不缓存世界矩阵；`c.dims` 可推 AABB。**不加 motionMode/velocity 等 D 专用字段。**
