日期：2026-08-06
状态：待实现
范围：vendor cannon.js 刚体引擎、纸箱物理化、蓄力投掷、顾客被砸倒地、散落箱局部绕行、存档朝向字段

## 0. 问题陈述

A（手感）、B（美术）、C（大卖场扩张）已完成。当前纸箱是纯运动学物件：`spawnBox` 落在卸货位、`putDownBox` 落在玩家脚下、`storeBox` 落在存储位，三处都是直接 `mesh.position.set(...)` + `rotation.set(0, yaw, 0)`，箱子永远平放、永远不动、永远互不接触。搬箱是唯一的物理性动作，而它感觉像拖动图标。

D 的目标是**只加一层玩具**：让纸箱变成真刚体，让玩家能把它扔出去看它翻滚、撞墙、砸倒顾客。这一层**不接入任何经济与玩法回路**——扔箱不扣钱、不降满意度、不算损耗、不触发投诉或罚款。它存在的唯一理由是手感与场景可信度。

因此本 spec 的每一条设计都要过同一道闸：**它会改变任何一个已有的数值/状态机/存档语义吗？** 会，就不做。

## 1. 决策锁定（用户已确认，不可更改）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **纯物理玩具，零玩法后果**：不扣钱、不降满意度、不算损耗、不触发投诉或罚款 | 一旦有经济后果，就必须给玩家反馈、给平衡、给存档、给断言——那是另一个子项目。本期的价值全部在手感 |
| 2 | **引擎 vendor `cannon.js 0.6.2`**（UMD 全局 `window.CANNON`） | 实证数据见 §2。唯一同时满足「file:// 可跑 + 纯 ES5 + 单文件 + 与 three r128 字段兼容 + MIT」的选项 |
| 3 | **物理范围只有纸箱**：商品单件、顾客均不参与物理 | 商品是 InstancedMesh（DESIGN §5.8），拆成独立刚体会直接推翻实例池架构；顾客参与物理会把导航、队列位、交易状态机全部拖下水 |
| 4 | **被砸反应 = 倒地 2.5 秒后原地爬起继续原行为**；**不改交易状态机、不加 `abortTx(reg)`** | 见 §7.1 的完整裁定 |
| 5 | **挡路 = 局部绕行**：顾客检测前方 ~1.2m 内的散落箱并侧向偏移。**不重建导航图、不把箱写进 `G.world.colliders`** | 箱一直在动，全量重建导航图不现实；写进 colliders 会同时改变玩家碰撞与射线遮挡（`player.occluded`），后果远超「绕开一只箱」 |
| 6 | **投掷 = 持箱时按住右键蓄力（~0.8s 满，HUD 力度条），松开右键扔出**；速度沿相机朝向，在「轻放」与「满力」之间按蓄力插值，附带随机角速度 | — |

### 1.1 决策 4 的完整裁定（C 期终审提出的 `abortTx(reg)` —— 不做）

C 期终审提出：「物理接管正在 `paying` 的顾客会让柜台被幽灵占 60s，需要 `abortTx(reg)`」。

**该担心的前提在本期不成立。** 它建立在「顾客本身是刚体、会被撞离队列位置」之上；决策 3 已经把顾客排除在物理之外，顾客不会移位。倒地是纯姿态动画（`c.mesh.rotation.x`），根节点 `position` 一帧都不动，2.5s 后原地爬起。

柜台被占的实际时长是 **2.5s**，相对 `CONFIG.patienceSec = 60`（data.js:55）的耐心上限可忽略，且倒地期间 `stepState` 照常推进（§7.3），耐心继续累计——不存在「砸倒顾客可以无限拖延耐心」的可利用漏洞。

**结论：不新增 `abortTx`，checkout.js 本期零改动。**

### 1.2 决策 4 的附带条款

顾客倒地时手上的商品**保持挂在手上跟随姿态旋转，不散落**。实现上零成本：`c.hands` 是 `c.mesh` 的子节点（customers.js:212-214），旋转根节点即整体跟随。

### 2.2 已知瑕疵（必须在实现里绕开）

**变步长路径下动态体的四元数插值是未实现的 TODO。** `World.prototype.step(dt, timeSinceLastCalled, maxSubSteps)`（`cannon.js:13191`）的插值块（`cannon.js:13226-13245`）只对 `STATIC` / `SLEEPING` 体 `copy` 四元数；动态体分支里只有一行注释：

```
// TODO: interpolate quaternion
// b.interpolatedAngle = b.angle + (b.angle - b.previousAngle) * h_div_dt;
```

**实测确证**（无头 Edge，`b2.angularVelocity=(0,5,0)`，30 帧变步长 `step(1/60, 0.017, 10)`）：

```
b2.quaternion.y              = 0.9477
b2.interpolatedQuaternion    = 0.0000, 0.0000, 0.0000, 1.0000   ← 永远是单位四元数
```

比「TODO」更严重：动态体的 `interpolatedQuaternion` **根本不会被写入**，它会永久停在初始的单位四元数。

**规避**：位置写回用 `body.interpolatedPosition`（平滑），旋转写回用 `body.quaternion`（只在物理步频更新）。`interpolatedQuaternion` 在本项目中**禁止使用**。

**第二处**：变步长路径的子步循环带实时保护（`cannon.js:13209-13212`）——`if (performance.now() - t0 > dt * 1000) break;`。卡顿时会丢子步，物理时间落后墙钟。对纯玩具无后果，记录在案。

### 2.3 步长与子步

主循环已把 dt 钳制在 0.1s（`main.js:137`：`tick(Math.min(dt, 0.1))`）。以 1/60 固定步长计，最坏 `0.1 / (1/60) = 6` 个子步，`maxSubSteps` 取 cannon 默认的 **10**（`cannon.js:13192`：`maxSubSteps = maxSubSteps || 10`）即安全，永不触发子步截断。

调用形式固定为 `world.step(1/60, dt, 10)`。

## 3. 架构与模块职责

### 3.1 新模块 `js/physics.js` → `G.physics`

职责单一：**拥有 cannon world、维护箱↔刚体绑定、每帧步进并把结果写回 mesh。** 不做别的。

| API | 契约 |
|---|---|
| `init()` | 建 `CANNON.World`（`gravity=(0,-9.82,0)`、`broadphase=NaiveBroadphase`、`solver.iterations=10`、`allowSleep=true`）+ 地面 plane + 天花板 plane。**必须在 `G.world.init(scene)` 之前调用**（world.init 会走到 `rebuildGraph → syncStatics`） |
| `syncStatics()` | 按 `G.world.colliders` **全量重建**静态刚体（先清后建）。地/天花板 plane 不参与重建 |
| `update(dt)` | `world.step(1/60, dt, 10)`，然后把全部 **loose** 箱的 `interpolatedPosition` / `quaternion` 写回 `box.mesh` |
| `attach(box)` | 由 mesh 当前 `position` / `quaternion` 建**动态**刚体，挂到 `box.rb` |
| `attachStatic(box)` | 同上但 `mass = 0`（存储位用，§3.4） |
| `detach(box)` | 从 world 移除 `box.rb`，`box.rb = null`。幂等 |
| `throwBox(box, dir, speed, spin)` | `attach(box)` 后设 `velocity = dir × speed`、`angularVelocity = spin` |
| `looseBoxes()` | 返回当前 loose 箱**实体**（不是 body）的数组，顾客侧只读，用于绕行与被砸判定。调用方从 `box.mesh.position` 与 `box.rb.velocity` 取值 |
| `_test` | `bodyCount()`（world.bodies 总数）/ `staticCount()`（**只数 collider 静态体 + 2 个 plane，不含 slotted 箱**）/ `stateOf(box)` / `stepOnce()` |

**不属于 `G.physics` 的**：被砸判定（归 customers，§7.2）、蓄力与投掷输入（归 player，§6）、箱实体的所有权（归 world，§3.3）。

### 3.2 唯一真相源：静态刚体从 `G.world.colliders` 自动生成

C 期反复吃过「同一事实存两份」的亏（beltFrame 双份、箱归属四处判据、drawcall 两个口径）。本期起手就断掉这条路：

**引擎静态刚体一律由 `G.physics.syncStatics()` 从 `G.world.colliders` 生成，绝不手写第二份几何表。**

`rebuildGraph()` 的三个调用点（`world.js:854` buildZone / `world.js:1011` syncLayout / `world.js:1341` init）**各自在其后加一行** `if (G.physics) G.physics.syncStatics();`。守卫 `if (G.physics)` 让 world.js 不硬依赖 physics.js。

漂移由断言 `physics.staticsMatchColliders` 钉死（§10 #2）：将来任何新增的 `rebuildGraph()` 调用点若忘了同步，断言立刻红。

### 3.3 箱实体归属仍归 world

`G.physics` **不持有箱的所有权**，只持 `box.rb` 引用：

- `allBoxes()`（`world.js:1187`）仍是唯一枚举口径，不变
- `destroyBox()`（`world.js:1216`）负责调 `G.physics.detach(box)`
- `spawnBox()` / `storeBox()` / `takeBox()` / `restoreBoxes()` 各自在自己的位置迁移点上做态转移

**命名裁定（重要）**：刚体引用**必须叫 `box.rb`，不能叫 `box.body`**。`box.body` 已经被占用——它是纸箱的**纸板 mesh**（`world.js:1252`：`var box = { mesh: group, body: body, label: label, ... }`），而且 `destroyBox` 会对 `[box.body, box.label]` 逐个 `geometry.dispose()` / `material.dispose()`（`world.js:1222-1227`）。用 `box.body` 装 cannon 刚体会当场把纸板 mesh 覆盖掉并让 dispose 对着刚体调用。

### 3.4 箱的三态

C 期把箱的归属判据散在 `isOnYard` / `slot.box` / `player.carrying` / `interactables` 四处。本期收敛成三个互斥态，并给出唯一判据：

| 态 | 唯一判据 | 刚体 | 交互体 | mesh 位置的写入者 |
|---|---|---|---|---|
| **held** | `G.player.carrying === box` | 无（`box.rb === null`） | 无（`pickUpBox` 已 `removeInteractable`，player.js:560） | `player.syncCarriedBox()` 每帧（player.js:285-292） |
| **slotted** | `storageSlotOf(box) !== null`（world.js:1198） | **静态**（`mass = 0`） | 有 | `world.storeBox()` 一次性写（world.js:789-790） |
| **loose** | 其余（在 `interactables` 里且不占存储位） | **动态** | 有 | `G.physics.update()` 每帧 |

**slotted 为什么用静态刚体而不是「无刚体」或「休眠动态体」**：
- 无刚体 → 扔出的箱会穿过仓库里码好的箱，观感断裂
- 休眠动态体 → 被撞醒后会离开存储位，而 `slot.box` 仍指着它 → 「slot.box 与实际位置不一致」正是 C 期「同一事实存两份」的复发
- 静态刚体 → 挡得住、推不走、`slot.box` 永远与位置一致

**四个转移入口**（每一处恰好一行物理调用）：

| 入口 | 位置 | 态转移 | 物理动作 |
|---|---|---|---|
| 拿起 | `player.pickUpBox`（player.js:555） | loose/slotted → held | `G.physics.detach(box)` |
| 放下 | `player.putDownBox`（player.js:567） | held → loose | `G.physics.attach(box)`（零初速） |
| 存入 | `world.storeBox`（world.js:785） | held/loose → slotted | `detach` 后 `attachStatic(box)` |
| 扔出 | `player.releaseThrow`（新增，§6） | held → loose | `G.physics.throwBox(box, dir, v, spin)` |

另外两处非玩家路径也必须走同一组调用：`world.spawnBox`（新箱落地 → loose 或 slotted，取决于 `atPos` 是否是存储位）、`world.takeBox`（slotted → held）。

### 3.5 地面与天花板

- **地面**：`CANNON.Plane`，`quaternion.setFromAxisAngle((1,0,0), -π/2)`，y = 0。无限平面 → 箱永不掉出世界
- **天花板**：`CANNON.Plane`，`quaternion.setFromAxisAngle((1,0,0), +π/2)`（法线朝下），**y = 3.40**

天花板高度 **3.40 = `WALL_H`(3.6) − 0.20**，不是 3.6，也不是 3.55。理由与实测见 §9.2。

天花板是无限平面，同时盖住户外卸货区——玩家在院子里往天上扔箱会撞到看不见的天花板。**这是有意取舍**：它让「箱体永远在 y ≤ WALL_H 之内」成为全图无例外的不变量，从而让阴影视锥结论成立（§9）。

### 3.6 主循环插入点

`main.js` 的 `tick(dt)`（main.js:141-158）现顺序为 `player → customers → checkout → shop`。**`G.physics.update(dt)` 插在 player 之后、customers 之前**：

```js
G.player.update(dt);
G.physics.update(dt);      // ← 新增
G.customers.update(dt);
G.checkout.update(dt);
G.shop.update(dt);
```

- **在 player 之后**：`player.update` 里 `doInteractions()` 会在松手那一帧把箱转成 loose 并给初速。physics 紧随其后步进，箱在同一帧就飞出去；反过来则会有一帧的「松手后箱悬在空中」。
- **在 customers 之前**：绕行（§8）与被砸判定（§7.2）都要读**本帧步进后**的箱位置与速度。放在 customers 之前，顾客当帧看到的就是最新箱位，不存在 1 帧滞后。
- 与 checkout / shop 的相对位置无所谓（两者都不读箱位），排在最后是既有顺序，不动。

`boot()`（main.js:102-127）里 `G.physics.init()` 插在 `G.world.init(scene)` **之前**：

```js
buildScene();
buildRenderer();
G.physics.init();          // ← 新增，必须在 world.init 之前
G.world.init(scene);
G.world.syncLayout();
...
```

## 4. collider 高度字段

### 4.1 为什么必须加

现有 collider 是纯 2D 的 `{ minX, maxX, minZ, maxZ [, zoneGate] }`。直接拿去生成刚体，一切都会变成墙高（3.6m）的墙——箱子永远扔不上货架、扔不上收银台、垃圾桶变成 3.6m 的柱子。

**方案：给 collider 加可选高度字段 `h`，缺省视为 `WALL_H`（3.6）。纯加法。**

寻路（`world.js:390` `segHitsBox`）与玩家碰撞（`player.js:275` `collidesAt`）只读那 4 个 2D 字段，`h` 对它们不可见，零影响。

### 4.2 高度表（视觉高度全部从建造代码实读）

| collider 来源 | world.js 行 | 满配数量 | 视觉高度实读 | **`h`** |
|---|---|---:|---|---:|
| 墙段 `wallAlongX` / `wallAlongZ` | 594 / 603 | 13（外墙 6 + 内隔墙 7） | `BoxGeometry(len, WALL_H, 0.2)` @ `y = WALL_H/2 = 1.8`（591-592 / 600-601）；`WALL_H = 3.6`（world.js:15） | 省略（默认 **3.6**） |
| 卷帘门 `buildShutters` | 616 / 620 | 3（开区后 `splice` 移除，world.js:847-849） | `BoxGeometry(w, 3.0, 0.12)` @ `y = 1.5`（612-618） | **3.0** |
| 世界边界围栏 | 693-698 | 6 | **无 mesh**（纯挡人体，只有 collider） | 省略（默认 **3.6**）——见下注 |
| 收银台 `buildRegister` | 726 | 3 | 柜体 `BoxGeometry(2.0, 1.0, 1.2)` @ `y = 0.5` → 顶面 1.0（716-718）；传送带 `BoxGeometry(1.6, 0.08, 0.9)` @ `y = 1.04` → 顶面 **1.08**（720-722），且 1.6×0.9 完全落在 2.0×1.2 的 collider 足迹内 | **1.08** |

| 垃圾桶 `buildTrash` | 760 | 1 | `CylinderGeometry(0.3, 0.25, 0.6, 8)` @ `y = 0.3` → 顶面 0.6（757-758） | **0.6** |

**围栏为什么保留 3.6**：它们没有 mesh，是纯粹的「玩家不许走出去」隐形墙。给它们物理高度 3.6 的效果是「扔到院子里的箱不会飞进虚空」——正是想要的。观感上院子确实四面无形墙，但这与玩家自身的行为一致（玩家也撞得到）。

**已知瑕疵**：垃圾桶是圆柱 mesh，collider 是 0.6×0.6 方盒，箱会以方形边界弹开。观感可接受，记录在 §11。

## 6. 投掷

### 6.1 输入分离：蓄力用右键（本 spec 消歧的关键一处）

左键当前已经有两个用途（player.js:484-520）：
- `mouseJustPressed` → `actionEdge`（与 E 键等价的「按一下」）
- `mouseDown` → `actionHeld`（持箱对着货架格按住不放 = 连续上架，player.js:517）

**裁定：蓄力投掷挂在右键（button 2）上，与左键完全分离——持箱时按住右键蓄力，松开右键扔出，与准星指向什么无关，左键的既有行为一字不动。**

**理由**：核实 `js/player.js:109-119`，`onMouseDown`（109）与 `onMouseUp`（116）分别在第 **110** 行与第 **117** 行以 `if (e.button !== 0) return;` 开头——两者都只处理左键（`button 0`），右键（`button 2`）在现有输入处理里**完全没有被占用**。把蓄力挂在右键上：
- 左键的两个既有语义（`mouseJustPressed` 点击交互、`mouseDown` 持箱按住连续上架）**零改动**，不需要任何 hover 类型判据；
- 彻底消除旧方案（左键蓄力、准星指着可交互物时左键仍是那个交互、只有指着空处才起蓄力）的手感成本——玩家想扔箱时无需先把准星移开货架/收银台/垃圾桶等交互体，对着货架也能直接蓄力扔出。

**中途失效**：蓄力过程中若 `inRegister` / 有全屏界面 / 失去指针锁定，**取消蓄力**（`charge = 0`，不投掷，箱留在手上）。player.js 现有的三处 `mouseJustPressed = false` 清理点（185-196、217-223）同时清 `charge`。

进入收银台时 `G.checkout.inRegister` 为真，`player.update` 早退（player.js:187-196），蓄力自然不会推进——与既有屏蔽一致，无需额外分支。

**实现要求：显式阻止右键的浏览器默认菜单。** 指针锁定状态下多数浏览器会抑制 `contextmenu`，但不能依赖这一点——必须在 canvas 上显式注册：

```js
domElement.addEventListener('contextmenu', function (e) { e.preventDefault(); });
```

验收断言 `player.contextMenuSuppressed`（§10 #17）校验该监听器已注册。

### 6.2 起点与方向

**起点 = 松手瞬间箱心的当前位置**，即 `syncCarriedBox()` 的同一式（player.js:288-290）：

```
origin = camera.position + camDir × 0.6 + (0, −0.35, 0)
```

`camera.position.y = EYE_HEIGHT = 1.65`（player.js:7, 227）。平视时 origin.y = 1.30；仰视 85°（`MAX_PITCH`，player.js:10）时 origin.y ≈ 1.90。

用同一式的意义：松手瞬间箱不跳变，视觉上是「手上的那只直接飞出去」。

**方向 = `camera.getWorldDirection()` 归一化后的相机朝向**，即 `_camDir`（player.js:288）。

**玩家自身移速不叠加到初速**（明确不做，§12）。

## 7. 顾客被砸

### 7.1 命中判定

顾客不参与物理，判定由 **customers.js 自己做**（`G.physics` 只提供 `looseBoxes()` 只读列表）。理由：customers 已经在遍历 `active[]`，把判定放在那里不需要新的遍历，也不会让 physics 反向依赖 customers。

**箱侧**：等效球，半径 **0.30**（介于内切 0.225 与外接 0.39 之间）。
**顾客侧**：直立圆柱，**旋转不变**（不需要跟着 `mesh.rotation.y` 变换）：

| 量 | 公式 | 取值范围 | 依据（customers.js） |
|---|---|---|---|
| 半径 `r` | `0.22 × c.dims.w + 0.13` | 0.32 – 0.40 | 最宽处是手臂：`armL/R.position.x = ±(0.22w + 0.07)`（208-210），臂宽 0.11（21）→ 半展 `0.22w + 0.125`，取 0.13 |
| 高 `top` | `1.77 × c.dims.h` | 1.59 – 1.91 | 最高处是头发：`hair.position.y = 1.70`（196）+ 最厚发型半高 0.065（28）= 1.765；`g.scale.y = h`（215） |
| `c.dims` | `{ h, w }`，`h = rand(0.90, 1.08)`、`w = rand(0.88, 1.22)` | — | 185-186, 224 |

**判定**：球心到圆柱轴（顾客 `mesh.position.x/z`）的水平距离 `< r + 0.30`，且球心 `y` 落在 `[−0.30, top + 0.30]`。

**触发阈值**：箱 `rb.velocity` 模长 **≥ 2.5 m/s**。低于此的滚动/推挤不触发（否则玩家轻轻把箱推到排队顾客脚边就把人放倒了）。

**每帧代价**：`active ≤ 20` × `loose ≤ 48` = ≤960 次平方距离比较，无分配。loose 数为 0 时整段跳过。

**收银员站桩不参与**：`cashierGroups`（world.js:545）不在 `G.customers.active` 里，没有 `c` 对象，天然不被判定。

### 7.2 倒地姿态

**关键前置**：`spawn()` 里给 `g.rotation.order = 'YXZ'`。默认 `'XYZ'` 下 `rotation.x` 绕的是世界 X 轴，顾客朝向 ±z 时会歪着倒；`'YXZ'` 下矩阵是 `Ry·Rx·Rz`，`rotation.x` 绕的是**朝向之后的自身左右轴**，正是「前扑 / 后仰」。**`rotation.x = 0` 时两种 order 完全等价，对既有行为零影响。**

朝向约定：`c.mesh.rotation.y = atan2(dx, dz)`（customers.js:316）→ 自身正前方是局部 +Z。`YXZ` 下绕局部 +X 正转把 +Y 推向 +Z，故：

- **`rotation.x = +π/2` = 前扑（脸朝下）**
- **`rotation.x = −π/2` = 后仰**

方向选择：箱速度在顾客朝向上的投影 `dot(v, forward)`——`> 0`（从背后砸来）→ 前扑；否则后仰。

**枢轴在脚下**（group 原点 y=0，DESIGN §5.7「根节点 y 恒 0」不破），倒下像伐木。躯干半厚 0.13 会有轻微入地，接受（顾客不参与物理，没有任何后果）。

### 7.3 时序

单变量 `c.ragdollT`（秒，从 0 累加）：

| 阶段 | 区间 | 行为 |
|---|---|---|
| 倒下 | 0 → 0.25s | `rotation.x` 由 0 线性插值到 `±π/2` |
| 躺平 | 0.25 → **2.50s** | 保持 |
| 爬起 | 2.50 → 2.85s | `rotation.x` 由 `±π/2` 线性插值回 0 |
| 结束 | ≥ 2.85s | `c.ragdoll = false`、`rotation.x = 0`、`c.ragdollT = 0` |

「倒地 2.5 秒」按决策 4 取**含倒下动作的躺平结束点**，爬起动画额外 0.35s。总占用 **2.85s**。

**倒地期间再次被砸**：不重播倒下动作，只把躺平计时拉回——`c.ragdollT = Math.min(c.ragdollT, 0.25)`。

### 7.4 倒地期间冻结什么、不冻结什么

| 项 | 倒地期间 | 理由 |

## 8. 局部绕行

### 8.1 算法

复用既有的车道偏移机制（customers.js:297-306）：`stepMove` 已经会把中途路点沿行进法向平移 `c.lane`。绕行只是**再叠加一个动态偏移 `c.avoid`**，走同一条法向。

每帧（`stepAvoid`）：

1. 若 `G.physics.looseBoxes()` 为空 → `c.avoid` 向 0 衰减，返回
2. 取当前行进方向 `f = normalize(path[0] − pos)`（`path` 空则返回）
3. 遍历 loose 箱，取满足下列全部条件中**最近**的一只：
   - 前向投影 `fp = dot(boxPos − pos, f)`，`0 < fp ≤ AVOID_RANGE`
   - 侧向偏移 `lat = cross_y(f, boxPos − pos)`，`|lat| < AVOID_HALF_W`
4. 命中 → 目标偏移 `target = −sign(lat) × AVOID_STEP`（`lat` 绝对值 < 0.05 时按 `c.id` 奇偶定侧，保证确定性、不抖）
   未命中 → `target = 0`
5. 平滑：`c.avoid += (target − c.avoid) × min(1, dt × 6)`

`stepMove` 里把 `c.lane` 换成 `off = clamp(c.lane + c.avoid, −0.80, +0.80)`，**包括第 302 行的退化保护判据**（`if (nl > Math.abs(off))`）——那行现在读的是 `c.lane`，必须一并改成 `off`，否则偏移量增大后退化保护失效，顾客会在路点附近来回摆动。

### 8.2 常量

| 常量 | 值 | 依据 |
|---|---:|---|
| `AVOID_RANGE` | **1.2 m** | 决策 5 |
| `AVOID_HALF_W` | **0.55 m** | 顾客半径 ≤0.40 + 箱半宽 0.225 −  重叠容差 |
| `AVOID_STEP` | **0.60 m** | 让开一个箱宽 + 半个身位 |
| 偏移总钳制 | **±0.80 m** | 主购物通道净宽 2.4m（DESIGN §5.10）→ 半宽 1.2m − 顾客半径 0.40 = 0.80。超过就贴到货架里 |
| 平滑系数 | `dt × 6` | 与 `applyGait` 的 `dt × 8`（customers.js:326）同数量级，观感一致 |

### 8.3 明确的失败模式（接受）

- 只偏移**中途**路点（`path.length > 1`），与 `c.lane` 同规则。箱正好落在终点/队列点上时顾客会直接走进去
- 绕行是**纯观感**：箱不在 `colliders` 里、顾客无碰撞体，绕行失败时顾客**直接穿过箱子**，无任何后果
- 不做多箱联合避让、不做前瞻多步、不做互避（GDD §6 明文「顾客可互相穿过」）

**钉死条款**：绕行期间 `G.world.colliders.length` 不变、`nav._nodes` 不变、`findPath` 结果不变（断言 §10 #18）。

## 9. 存档、阴影、性能

### 9.1 性能预算

**实测**（无头 Edge，`libs/cannon.min.js`，NaiveBroadphase，`solver.iterations = 10`，300 步取分位）：

| 场景 | 静态 | 动态 | 总体 | avg | p50 | p95 | max |
|---|---:|---:|---:|---:|---:|---:|---:|
| 早期探测（44 静态 + 地面 + 48 动态） | 45 | 48 | 93 | **0.90ms** | — | **1.7ms** | **2.6ms** |
| 本 spec 口径 · 典型（24 箱在库、24 只散落） | 49 | 24 | 73 | **0.89ms** | 0.80 | **1.80ms** | **2.60ms** |
| 本 spec 口径 · 最坏（48 只散落且**全部不休眠**） | 49 | 48 | 97 | **1.49ms** | 1.30 | **2.30ms** | **3.30ms** |
| 同上但用 SAPBroadphase | 49 | 48 | 97 | 1.46ms | 1.40 | 2.30ms | 3.10ms |

> 实测配置用 **49** 个静态体（47 个 collider 盒 + 2 plane），比 §4.3 算出的满配 46 多 3 个（多算了 3 扇开区后已移除的卷帘门），即**实测比真实满配更保守**。

**结论**：
- 预算 **≤ 3.5ms/帧**（16.7ms 帧预算的 21%）。最坏场景实测 p95 2.30 / max 3.30，达标
- 最坏场景是人为构造的（`allowSleep = false` 强制 48 只箱全程醒着）。实际启用休眠后堆稳的箱退出求解，典型成本远低于此

### 9.2 阴影视锥 —— 裁定：**不需要改**

**估算方法**：箱抛物线最高点在没有天花板时可达 `origin.y + v²sin²θ/(2g)`；`THROW_V_MAX = 9.0`、`origin.y ≤ 1.90`、竖直上抛 → 理论顶点 **6.02m**，远超墙高。所以**天花板 plane 是唯一有效的约束**，视锥问题被转化为「天花板放多高」。

**实测扫描**（12 只箱、随机初始角速度、各步进 300 步，取 `body.aabb.upperBound.y` 全程最大）：

| 天花板 plane y | v₀ = 9.0 m/s | v₀ = 12.0 m/s（超压测试） |
|---:|---:|---:|
| 3.55 | 3.6649 ✗ 超 0.06 | 3.7041 ✗ 超 0.10 |
| 3.45 | 3.5682 △ 余量 0.03 | **3.6245 ✗ 超 0.02** |
| **3.40** | **3.5115 ✓ 余量 0.09** | **3.5177 ✓ 余量 0.08** |
| 3.35 | 3.4380 ✓ 余量 0.16 | 3.5177 ✓ 余量 0.08 |

> **本表由 `G.physics._test.probeCeiling` 的出厂配置产出（D-T1 修复轮 2 重跑，全列可复现）。改动探针初值、初始角速度、箱数或步数后必须重跑本表。**
> 数值判定口径与断言 `physics.ceilingCaps` 完全同源（同一个函数、同样两个 v₀），故表里任何一格 ✗ 都等价于该断言变红。
> **修复轮 2 更正**：本表原先的 `v₀ = 12.0` 一列不可复现（原写 3.45 → 3.5605 △、3.40 与 3.35 同为 3.5367 ✓）。实测 **3.45 行 v₀=12.0 是 3.6245，已超 `WALL_H`**，该行两列不能都标 △。此前一轮审查照原表重推，得出「`CEIL_Y = 3.45` 时 `ceilingCaps` 仍全绿」的错误结论，即源于这一格。
> 另：3.40 与 3.35 两行在 `v₀=12.0` 下确实**同为 3.5177**——这是探针的真实平台区（`CEIL_Y ∈ [3.40, 3.42]` 该列恒为 3.5177，降到 3.30 才随之下降），**「相邻两行数值相同」本身不是错数的证据**，不要据此判断表是否陈旧；判断依据只能是重跑。
> 更准确的病因：**整张表早于当前 `probeCeiling` 的定型配置**——只有 `CEIL_Y = 3.40` 这一行的 `v₀=9.0` 值（3.5115）与出厂探针逐位吻合，其余各行在小数第 2-3 位就开始偏离。表是用一版更早的探针参数产出的，不是单独某一列抄错。

求解器允许的穿透 + 箱以角朝上撞击时 aabb 顶比 plane 高出约 0.17m，所以 plane 必须比 `WALL_H` 低 0.2 才能保证 `aabb.upperBound.y ≤ WALL_H`。**取 `CEIL_Y = 3.40`。**

**`CEIL_Y` 还被第二条独立约束钉住**（D-T1 修复轮 1 追加）：门洞处墙体断开，关闭的卷帘门静态体只到 `h = 3.0`，其上到 `WALL_H` 的空当只由天花板 plane 压住，空当 ≥ 箱边长 0.45 就能隔着关着的门往未购区域扔箱。本表的阴影约束与它在 `WALL_H = 3.6` 下**恰好同阈值（都在 3.45 变红），纯属巧合**：`WALL_H = 4.0` 时本表可放行到 `CEIL_Y = 3.83`（实测 3.9714 ✓，3.84 → 4.0105 ✗），而门顶空当已达 **0.83 ≫ 0.45**，exploit 大开而本表毫无察觉。故门控由独立断言 `physics.ceilingSealsZoneGates` 承担，见 CONTRACTS 不变式段。

**由此得出的不变量**：全图任何箱的几何体永远在 `y ≤ 3.6 = WALL_H` 之内。

**为什么这就够了**：现有断言 `shadow.frustumCovers`（main.js:830-869）以 `y = 0 .. WALL_H(3.6)` 采样**全部 collider 的 8 个角点**，C 期终审实测最小余量 **0.73m @ (20.4, 3.6, 10.2)**（东院围栏东北角）。阴影视锥是**凸**体（正交框 + near/far），采样点全部在内 ⇒ 其凸包全部在内。箱的可达空间（x ∈ [−20, 20]、z ∈ [−10.5, 10.5]、y ∈ [0, 3.6]，全部被墙与围栏 collider 围住）是该凸包的子集。

**灯光/视锥参数一律不动**：`sun.position (8,14,6)`、ortho ±26、`near 0.5`、`far 60`、`mapSize 4096²`（main.js:38-50）。

**加一条断言把不变量钉死**（§10 #4），而不是改视锥。

### 9.3 存档结构变更

现状（state.js:105，`gss-save-v2`）：`boxes: [{ pid, left, where, slotId? , x?, z? }]`（`world.serializeBoxes`，world.js:1262）。

**新增一个字段：`ry`（绕 Y 的偏航，弧度）。**

**序列化规则（一条规则同时解决「朝向」与「飞行中」两个问题）**：

> 所有箱一律按**落地平放**口径存档：`y` 恒为 0.225（不入档，读档时写死）、姿态**只取偏航**。

- `ry = new THREE.Euler().setFromQuaternion(box.mesh.quaternion, 'YXZ').y`（`slotted` / `held` 恒为其现有 `rotation.y`）
- 俯仰与翻滚**丢弃**
- 飞行中的箱不需要任何特判——它天然走同一条规则（x/z 取当前值、y 归 0.225、只留偏航）

**为什么不存完整四元数**：存四元数后读档要么允许箱以角着地（`y = 0.225` 会穿地，需要额外存高度），要么要在读档时做落地解算。存偏航则**任何存档状态都对应一个合法静止姿态**，读档必不穿地、不需要额外字段、与 `putDownBox`（player.js:572）与 `storeBox`（world.js:790）现有的 `rotation.set(0, yaw, 0)` 口径完全一致。

**读档**（`restoreBoxes`，world.js:1285）：`spawnBox` 落位后设 `mesh.rotation.set(0, ry || 0, 0)`，`attach` 后立即 `rb.sleep()`——读完档满地箱不会同时醒着抢一帧。

**降级**：旧档没有 `ry` 字段 → 视为 0，与现状完全一致（现状所有箱 yaw 都是玩家放下时的朝向或 0）。不需要版本号变更，`v: 2` 不动。
