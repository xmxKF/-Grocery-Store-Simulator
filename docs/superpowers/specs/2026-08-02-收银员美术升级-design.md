# 收银员站桩美术升级（小任务）— 设计文档

日期：2026-08-02
状态：待实现
范围：world.js 收银员站桩换用 B 期顾客构造；跨模块接口 `G.customers.buildFigure(opts)`

---

## 1. 问题

B 期把顾客升级为 9 件三色构造后，`world.js:455 buildCashierFigure` 仍是旧 4 件方块人（躯干 1.0 高 vs 顾客 0.68、无臂无发无鞋），站在队首顾客旁——收银台是全店视觉对比最强的位置。

## 2. 设计

### 2.1 跨模块接口（契约先行）

`customers.js` 的私有 `buildBody()` 改签名为 `buildBody(opts)`，`opts` 可选对象：`{shirt, pants, skin, hair, hairStyle, h, w}`——每个省略项走现有随机逻辑（`spawn()` 无参调用，行为零变化；`_test.spawnOne` 同）。新增公开导出：

```js
G.customers.buildFigure(opts)   // -> {group, hands, shirtMat, torso, head, hair, legL, legR, armL, armR, dims, baseY}
```

薄包装 `buildBody(opts)`。登记进 CONTRACTS.md G.customers 段。

### 2.2 world.js 消费

`buildCashierFigure()` 改为：

```js
  function buildCashierFigure() {
    var body = G.customers.buildFigure({
      shirt: '#4C9BE8',   // CONTRACTS：制服固定色
      pants: '#2E3742',
      skin: '#D9A878',
      hair: '#2A2118',
      hairStyle: 0,       // 短块：深度 0.29 ≤ 0.3m 空隙（后长 0.34/平顶 0.31 超限；蓬顶 0.24 亦可，取短块为定妆）
      h: 1.0, w: 1.0
    });
    var group = body.group;
    group.position.set(-7.75, 0, 0);
    group.rotation.y = Math.PI / 2;   // 面朝 +x：传送带 / 排队方向
    return group;
  }
```

旧 4 件构造删除。几何余量核算：旋转 90° 后身体局部 z 占世界 x——躯干深 0.26×0.9=0.234、鞋 0.22、短块发 0.29，均 ≤ 空隙 0.30。

### 2.3 不做

- 无待机动画（站桩，YAGNI）；`hands` 空组保留无害
- 阴影沿 buildBody 现有逻辑（躯干/头/腿 cast per `G.tex.on`），与 DESIGN §5.5 收银员行（cast ✓ / receive ✗）一致
- `setCashierVisible` 幂等语义、enterRegister 临时隐藏流程零改动

### 2.4 文档

- CONTRACTS.md：G.customers 段补 `buildFigure(opts)` 签名（含 opts 字段表与「省略项随机」语义）；`:182` setCashierVisible 条款的「体型同顾客规格」保持（现在字面为真）
- DESIGN.md §5.7 尾补一行收银员固定参数表

### 2.5 验收

自测断言（`?selftest=1`，无头可跑）：

- `world.cashierFigure`：`setCashierVisible(true)` 后，场景中定位 `position.x === -7.75 && position.z === 0` 的 Group（位置全场唯一，不可按色搜——顾客衬衫板含 #4C9BE8），断言子树 mesh 数恰 9、其 shirtMat 色为 `0x4C9BE8`
- `world.cashierIdempotent`：连续两次 `setCashierVisible(true)` 场景中该组仅一份；`setCashierVisible(false)` 后移除
- 既有 82 断言零回归（尤其 checkout 链路与 perf.drawCallCeiling——收银员 4→9 mesh，闸门实测应 ~507，仍 <550）
