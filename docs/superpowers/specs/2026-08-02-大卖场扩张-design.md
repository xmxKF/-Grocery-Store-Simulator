## 0. 背景与决策来源

A（手感）、B（美术）、收银员小任务已完成。C 实现用户的原始诉求「地图扩大到类似原作的大超市、非常多个收银台与仓库与货架」。

设计经 Opus + Codex 并行盲测综合（10 处分歧裁定 + 吸收 Codex 四个防御性好点，全记录于 §1）。

### 用户已锁定决策（五连确认）

1. **扩张形态**：大壳分区开放——32×20m 外壳一次建好（建筑/collider 静态），内部 3 购物区 + 1 仓库间，卷帘门封锁、等级+金钱购买开放，寻路图节点门控
2. **规模**：16 组货架 + 4 冷藏（**120 格**）、3 收银台、顾客上限 ~20、仓库 1 间
3. **仓库**：存储货架——24 箱位、放/取箱交互、入存档、送货迁仓库门口、满仓拒收
4. **多台**：每台独立雇佣（¥200+¥60/天）、玩家随时接管任意台、雇员自动结账 XP 减半、顾客排最短队；**收银台 ②③ 随区域 B/C 解锁附带**（不单独购买）
5. **存档**：断代 `gss-save-v2` + v1 轻量迁移（继承钱/XP/等级/许可/定价；货架库存按**进价全额**折现入余额；旧键保留可回退）

### 必须偿还的债务

- checkout.js `beltFrame` 单例缓存 + `findBeltMesh` 全场景 traverse（多台必炸）→ §3 根治
- `freeYardSlot` 溢出叠箱无上限 → §5 根治
- `TAG_TEX` 改价累积不 dispose → §8 T7 治理（键降为 `pid|state`、改价 dispose 旧条、上限 72）
- GDD §14 曾裁剪「多收银台」「员工寻路 AI」→ T0 修订（多收银台入正文；员工寻路仍不做）
- CONTRACTS「顾客走 waypoint 直线无需寻路」承诺 → T0 作废改为 `nav.findPath` 契约

## 2. 布局（32×20 大壳）

原点居中，x∈[-16,16]、z∈[-10,10]，`WALL_H` 3.0→3.6。东进东出（顾客门东墙 z[4.4,6.2]），南侧前厅收银，西侧仓库+卸货。

```
z=-10 ┌──────────────── 区域 C  z[-9.8,-4.2]（Lv8 ¥3200，附带 R3）──────────┐
z= -4 ├── 内墙 z=-4 全宽，卷帘门 C @ x[3,5] ───────────────────────────────┤
      │ 区域 B  x[-15.8,-0.2] z[-3.5,3.5]   │ 区域 A  x[0.2,15.8] z[-3.5,3.5]│
      │ （Lv5 ¥1500，附带 R2）              │ （开局）                        │
z= +4 ├ 内墙 z=+4 @ x[-16,0]，卷帘门 B @ x[-5,-3] ┤  A↔前厅无墙开口          │
      │ 仓库 W x[-15.8,-8] z[4.2,9.8]       │ 前厅+收银 x[-8,16] z[4,10]     │

z=+10 └──────────────────────────────────────────────────────────────────┘
```

### 2.1 货架排布（16+4 组 = 120 格）

| 区 | 内容 |
|---|---|
| A | 货架 x=3,7.5,12 @ z=-1.6；货架 x=3 @ z=+1.6；冷藏 x=7.5,12 @ z=+1.6（aisleZ=0）——4 架+2 冷 |
| B | 货架 x=-13.5,-10,-6.5 @ z=∓1.6 两行；冷藏 x=-2.5 @ z=∓1.6（aisleZ=0）——6 架+2 冷 |
| C | 货架 x=-12,-6,0,6 @ z=-8.6；货架 x=-12,-6 @ z=-5.4（aisleZ=-7.0）——6 架 |

冷藏全部在 A/B：生鲜许可（Lv3）时 A 必已开放，不会「有证无柜」。

**`buildRack` 两处地基改造**（Opus 风险提示①）：`facing = (aisleZ > centerZ) ? 1 : -1`（现硬编码 `centerZ<=0`）；`aisleSpot = (centerX, 0, aisleZ)`（现硬编码 z=0）。货架一律轴对齐不旋转（collider 是纯 AABB）。

### 2.2 收银区

柜台几何转 90°：`Box(2.0, 1.0, 1.2)` 长轴沿 x，中心 z=7.6；R1 x=-2（开局）/ R2 x=4 / R3 x=10。`front=(x,0,6.8)`，queueSpots z=6.2→3.8 五点；玩家站位由 beltFrame 反推落在 z≈8.5（南侧员工通道 z[8.2,9.8]）。电脑 (14,9.4)；垃圾桶 (-15,9.4)（仓库内近卸货门）。`nav.entry=(15.2,0,5.3)`、`nav.exit=(18,0,5.3)`。

### 2.3 卷帘门与扩建交互

卷帘门 mesh 注册 `type:'shutter'`，提示 `[E] 开放区域 B（¥1500 · 需 Lv5）`；条件不足红字 prompt 给原因（DESIGN §6 规范）。购买成功：门升起（或隐藏）、移除门 collider、启用该区 nav 节点、`syncLayout` 惰性建造该区货架/收银台。**不加电脑页**（避免同一动作两个真相源）。

### 2.4 视觉配套（与 T1 同 commit，Opus 风险提示②）

阴影视锥 ±13→**±26**、far 40→**60**、mapSize 2048→**4096**（保 ~1.27cm/texel）；fog 30/90→**45/140**；`shadow.frustumCovers` 断言先红后绿是天然验收锚点。

## 3. 多收银台（checkout.js 重构）

**单例状态全部下沉 `registers[i]`**：`{ ref /*world 侧*/, queue:[], tx:null, frame:null, stance:null, staffed:false, cashierGroup:null, cashierHidden:false }`；模块级仅存 `activeReg`（玩家当前台，至多一个）与 `stepSlides/stepTween/scanCd`（只对 activeReg 有意义）。

- world.js 提供 `G.world.registers = [{ index, mesh, beltMesh, front, queueSpots[5], zone }]`，按区域解锁惰性建造；belt 带 `userData.belt` + `userData.registerId`。`nav.registerFront/queueSpots` 删除（改 `nav.registers`）。
- `frameOf(reg)`：`reg.frame || (reg.frame = computeFrame(reg.ref.beltMesh, reg.ref.front))`——债务 #1 根治，`findBeltMesh` 整段删除。
- `update(dt)`：逐台 `prune/retarget/promoteHead/stepTx`。
- **并发规则**：雇员自动结账条件 = `reg.staffed && activeReg !== reg`（玩家接管哪台雇员让位并隐藏站桩）；XP 减半延续。`completeSale` 只碰 `reg.tx`；共享写只有 `G.addMoney/dayStats`，同帧顺序执行无竞态。
- `enterRegister(reg)`：已占别台时忽略并 prompt「先退出当前收银台」；player.js 交互传 `entry.data.register`。
- 扫码：mousedown 只收集 `activeReg.tx.items`；item mesh `userData = {registerId, txId}`，命中后双重核验（Codex 防串台）。
- `joinQueue(c)`：取已建台中 `queue.length` 最小者（并列取低 index）。
- `_test`：`tx(i)/scanAll(i)/settle(i)/payCard(i)`，**i 缺省 0**（现有调用点零改动）；新增 `_test.registers()`。
- 雇佣：`G.shop.hireCashier(i)/fireCashier(i)`；`'cashier'` 事件 payload 加 `index`；`G.state.cashier` 废弃 → `G.state.registers[i].staffed`。
- 日结判定不改。

## 4. 寻路（world.js nav 图）

- **节点**（全部从布局表推导）：每 rack 的 aisleSpot、过道端点、卷帘门内/外两点、entry/exit、每台 register front + 5 queueSpots、仓库存储位前点、卸货区中心。~60 个。
- **边**：两两配对，「轴对齐（|Δ|<0.05）+ 距离 ≤10m + 线段对膨胀 0.45m 的 collider 无交」即连边，权重=距离；线段-AABB 判定在 world.js 自持一份（不跨模块调 player 的）。
- **门控**：`node.zone ∈ {core,A,B,C,W}`，`node.enabled = zones[zone]`；关闭的卷帘门同时有 collider 挡玩家。开区时置位节点 + 移除 collider，不重建图。
- **API**：`G.world.nav.findPath(from, to) -> [Vector3]`——两端 snap 到最近的视线通畅 enabled 节点，Dijkstra，返回折线；不可达返回 `[]`（customers 视为该目标不可达，pickTarget 跳过）。
- **customers.js 唯一改动**：`moveTo(v) { this.path = G.world.nav.findPath(this.mesh.position, v); }`。stepMove/atDestination 逐点消费不改。
- **车道偏移**：生成时 `c.lane = G.rand(-0.35, 0.35)`，stepMove 把中途目标点沿当前段法向平移 lane（队列点与 register front 不偏移）。零状态零交互开销。
- 玩家不寻路（WASD + AABB 照旧，关闭区靠门 collider 挡）。

## 5. 仓库

- `storageSlots`：24 个（2 组存储架 × 12），`{ id:'st0_5', pos, marker, box:null|箱实体 }`，注册 `type:'storage'`。
- 交互（player.js 加分支）：持箱对空位 `[E] 放入纸箱` → `G.world.storeBox(slot, carrying)`；空手对有箱位 `[E] 取出纸箱（名 ×N）` → `G.world.takeBox(slot)`；不匹配红字。
- 序列化：`storage: [{id, pid, left}]`（只存有箱位）；restore 走 `spawnBox(pid, atPos)`——签名扩为可选定点，现有调用零改动。
- 卸货区迁至 x[-19.4,-16.6] × z[4.5,9.5] 的 3×4=12 位，与 `maxBoxesInYard=12` 对齐。
- **债务 #2 根治**：`freeYardSlot()` 满返回 null；`spawnBox` 收到 null 不生成，`shop.update` 把该箱放回配送队列（`remaining=2`）并 toast「卸货区已满，配送车在门外等待」。
- 满仓拒收在 `orderBoxes` 校验（`yard 现有 + 配送在途 + 本单 > 12` 即拒，按钮禁用 + 提示）；仓库 24 位不计入订单校验（玩家自搬的缓冲）。

## 6. 等级 / 经济重平衡

| Lv | 累计XP | 解锁（★=付费购买） |
|---|---|---|
| 1 | 0 | 区域 A（4 架=24 格）+ R1；食品/饮料证 |
| 2 | 60 | 日用品证 ¥120；大米/抽纸/洗手液 |
| 3 | 160 | 生鲜证 ¥350（附 A 区 2 冷藏 → 36 格）；★**仓库 ¥900**（24 箱位，送货点迁仓库）；橙汁/苹果/香蕉 |
| 4 | 320 | 巧克力/茶饮/鸡蛋 |
| 5 | 550 | ★**区域 B ¥1500**（6 架+2 冷藏 → 84 格，**附带 R2**）；咖啡/牛奶/洗衣粉 |
| 6 | 850 | 金枪鱼/吐司/牙刷 |
| 7 | 1250 | 单次订货 8→12 箱；能量饮/垃圾袋 |
| 8 | 1750 | ★**区域 C ¥3200**（6 架 → 120 格，**附带 R3**）；生菜 |
| 9 | 2400 | 电池 |
| 10 | 3200 | 可雇收银员（**每台** ¥200+¥60/天）；顾客上限 20 |

- 房租：`40 基础 + 仓库 20 + B 30 + C 40` → 全开 ¥130/天（`CONFIG.rentPerZone`；删 Lv8 翻倍规则）。水电不变（架 2/冷藏 4 → 全开 ¥48）。工资 `staffed 台数 × 60`。全开满员固定支出 ¥358/天。
- `spawnInterval = clamp(20 − 0.8(day−1) − 1.2(level−1) − 2.0·zonesOpen, 3.0, 20) × rand(0.75,1.25)`（zonesOpen = 已开购物区数−1 ∈[0,2]）。
- `concurrentCap = clamp(4 + level + 3·zonesOpen, 5, 20)`。
- 许可证价不动。经济核算：Lv10 全开 300s 约 60-80 单、客单 ~¥12、毛利 ~45% → 日毛利 ~¥400 覆盖 ¥358 留净利。

## 7. 存档 v2 与迁移

```js
{ v:2, money, day, xp, level, prices, licenses, negDays,
  zones:{A:true,B:false,C:false,W:false},
  registers:[{owned,staffed}×3],
  shelves:[{id,productId,count}], storage:[{id,pid,left}] }
```

- 读取分流（state.js）：优先 `gss-save-v2`；无则读 v1 → `migrateV1`：继承 money/day/xp/level/prices/licenses/negDays；`cashier → registers[0].staffed`；zones 全锁（仅 A）；**shelves 不继承 → `money += Σ count×cost`（全额折现常量 MIGRATION_REFUND_RATE=1.0）**，记 `G.state._migrated={refund}`；首次 save 写 v2；**v1 键保留**。`resetSave` 双键清除。
- 字段级降级（Codex）：level 钳 1-10、prices 过滤未知 pid/非正数回退 `market×1.2`、licenses 与现有类目求交并保底食品/饮料；坏字段回默认不弃整档。
- 读档顺序硬约束：先写 zones/level/licenses → `syncLayout()` → `restoreShelves/restoreStorage`。
- 迁移提示：`main.startGame()` 后检 `_migrated`，toast「存档已升级：店铺按新布局重建，原货架库存 ¥XXX 已按进价折现入余额」。
